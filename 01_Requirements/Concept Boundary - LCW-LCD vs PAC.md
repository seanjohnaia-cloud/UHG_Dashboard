# Concept Boundary Clarification — LCW/LCD vs PAC

## User Clarification

The user clarified that while both concepts are internal-facing, they operate at different levels:

1. The **LCW/LCD workbook currently being examined is customized to UHG only**.
2. That workbook was the user's attempt at automation for UHG-specific project management/data handling.
3. **PAC is a broader framework concept** that captures all processes required to start a project at Grace.

## Corrected Concept Boundary

| Concept | Scope | Nature | Current Status |
|---|---|---|---|
| LCW/LCD Workbook | UHG-specific | User-created automation/data-management attempt customized to UHG | Source/design precedent for UHG Dashboard only |
| PAC | Grace-wide | Framework for all processes required to start a project at Grace | Developmental structure candidate requiring review |

## Consequence

Do not treat the UHG LCW/LCD workbook as the universal PAC model.

Instead:

```text
LCW/LCD = UHG-specific automation attempt / evidence of one client-specific operating model
PAC = broader Grace project-start framework that may use lessons from UHG but must not be reduced to UHG
```

Additional clarification:

```text
Generic LCD-W = typical/common Grace project data worksheet for most projects
UHG LCD/LCW = atypical client-specific framework because UHG has an established, contractually binding framework
PAC = Grace-wide project-start framework that still supplies needed info before/at notice to proceed
```

For UHG, the work is specifically using the UHG LCD/LCW because the client framework is contractually binding. For most projects, a generic LCD-W may suffice.

## Governance Note

Building PAC would change developmental structure. Per user governance preference, PAC should be discussed and reviewed before implementation.

## Open Naming Note

The current workbook file is named:

```text
!_LCD Workbook.xlsx
```

The user referred to it here as **LCW**. Until the naming is resolved, use `LCW/LCD` when referencing the workbook as a source artifact, and avoid turning either acronym into a universal system concept.
