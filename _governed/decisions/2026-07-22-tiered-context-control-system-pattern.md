# Decision: Tiered-context / concurrence-gate control system — accepted as candidate Pii-generic core (narrowed)

## What is accepted

The five-layer control system is accepted as this project's operating pattern and as a **candidate** Pii-generic core pattern:

```text
1. Tiered context      — resident / state / deep / archival, mapped onto _governed/ layers;
                         deterministic metadata-driven loading; depth escalation triggered by
                         structure (conflict/assumed states, decision citations), never by
                         model confidence
2. Concurrence gate    — per the companion decision of this date (resident-context concurrence rule)
3. Gate-health metrics — approval streaks; dialogue effectiveness by outcome; latency AND depth
4. Reality audit       — designated QC person, print-to-reality, human to human; correspondence
                         (record vs. world), which no internal coherence check reaches;
                         risk-weighted sampling
5. Feedback            — audit findings re-enter as raw/ records, drive conflict field states,
                         and flow through the same pending→concur pipeline
```

Supporting multi-agent rules accepted with it: agent partitioning by governed layer (scoping/workers/orchestrator); governed handoffs carrying PI metadata (no provenance laundering); the **single-pen rule** — only the orchestrator writes to `memory/pending/`, with the worker chain recorded in provenance.

## The narrowing (explicit, per decider)

Accepted as **candidate Pii-generic core, pending the generalization test against a second project** (Dunham Dining Hall, LPSO Work Release, or LUC). Until that test runs and a superseding decision promotes it, this pattern:

- **binds this project** (UHG_Dashboard specimen) — tooling, dashboard, and agent behavior here may rely on it;
- **does not bind the Pii core schema** — it may not be cited as settled generic-core structure in other projects or in Pii-core synthesis without noting its candidate standing.

This narrowing follows the established client-overlay triage rule: patterns observed in one specimen project are candidates for core promotion, not automatic core.

## Explicitly not decided here

- Human-declared per-session context mode (open question).
- Reasoning-architecture selection per task class (open question).
- Concrete proposal-format/triage specifications and audit sampling parameters (implementation follow-ups).
- The operational-data-layer candidate decision (separate record, still candidate — its blocking questions remain open).
